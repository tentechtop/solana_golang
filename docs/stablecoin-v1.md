# 稳定币 v1 实现与运行说明

本版本接通 Ordexus APP、链上执行与公开 RPC，采用**发行方声明储备、线下收付款**模式。链上强制权限、数量守恒和订单状态；不会查询银行余额，也不保证代币市场价格。银行收款、付款、凭证真实性由发行方核实，自动银行 API、KYC 和多签托管尚未接入。

## APP 操作

入口：钱包底部 **资产 → 标题右侧稳定币**。

1. 连接运行本版本的链节点，准备原生币支付手续费和账户租金。
2. 在“创建币种”填写名称、符号、锚定货币代码、精度（0–9）和发行上限。APP 原子部署不可升级模板、创建币种和发行方余额账户；初始供应量为 **0**。
3. 发行方收到线下资金后，在币种“发行”填写接收钱包、数量和唯一到账凭证编号。核实后预览并广播；首次收款会自动创建接收人的资产账户。业务凭证只上链 SHA-256，不上链银行卡号。
4. 持有人可转账、申请赎回或销毁。赎回销毁对应流通量，并等额记入待兑付；普通销毁不会创建付款订单。
5. 发行方在订单页领取赎回订单，等待**最终确认**后，使用该订单地址作为线下付款幂等键。付款已完成后登记付款凭证并结算；付款最终失败或已撤销且确定不再扣款时，登记失败凭证并退币。
6. 待领取的赎回可由持有人或发行方取消并退币。处理中订单仅发行方能结算或执行失败退币；完成或取消后不可重复操作。付款结果未知时保留处理中状态，继续核查原付款。

当前发行权限由一个钱包签名控制，交接采用提议、接任者签名接受两阶段操作。暂停会阻止新增发行、转账、赎回申请和普通销毁；已有订单的兑付和退款仍可处理。发行上限不得低于流通量加待兑付量。

## 账务与状态

全链路金额为 uint64 最小单位；JSON 为十进制字符串，APP 以 BigInt 计算。始终要求：

`流通供应量 + 待兑付数量 <= 发行方声明储备`，且 `<= 发行上限`。

| 操作 | 流通量 | 声明储备 | 待兑付 |
| --- | --- | --- | --- |
| 到账发行 A | +A | +A | 不变 |
| 转账 A | 不变 | 不变 | 不变 |
| 申请赎回 A | -A | 不变 | +A |
| 结算兑付 A | 不变 | -A | -A |
| 取消 / 失败退币 A | +A | 不变 | -A |
| 普通销毁 A | -A | 不变 | 不变 |

同一币种的到账凭证哈希绑定唯一发行订单，发行权限交接后也不能重复使用。不同编号是否代表同一笔银行资金仍须线下对账。赎回编号按持有人、币种绑定；链上公开地址和数量，哈希不应承载低熵敏感信息。

状态账户 kind 分别为 16（币种）、17（余额）、18（订单），版本 1。保持原通用资产 kind 1–3 和指令 0–7 的编码不变。稳定币入口独立限制为不可升级模板，普通资产模板不能调用稳定币指令。

指令沿用 `u32 type | u64 amount | u8 decimals | string name | string symbol | string URI`，字符串为 Borsh。除创建外，decimals/name/symbol 必须为空或零；下表未注明数量的操作 amount=0。所有首账户均为操作者并要求真实钱包签名。

| 编号 | 操作 | 指令账户（依次） | URI |
| --- | --- | --- | --- |
| 100 | 创建，amount 为上限 | 创建者、币种 | 三字母货币代码 |
| 101 | 开户 | 付款人、币种、余额 | 持有人原始公钥 |
| 102 | 发行 | 发行方、币种、接收余额、发行订单 | 到账凭证哈希 |
| 103 | 转账 | 持有人、币种、来源余额、接收余额 | 空 |
| 104 | 申请赎回 | 持有人、币种、余额、订单 | 申请编号哈希 |
| 105 | 结算 | 发行方、币种、订单 | 付款凭证哈希 |
| 106 | 取消 | 持有人或发行方、币种、持有人余额、订单 | 空 |
| 107 | 领取 | 发行方、币种、订单 | 空 |
| 108 | 暂停，amount=0/1 | 发行方、币种 | 空 |
| 109 | 提议发行方 | 发行方、币种、接任者 | 空 |
| 110 | 接受权限 | 接任者、币种 | 空 |
| 111 | 调整上限 | 发行方、币种 | 空 |
| 112 | 普通销毁 | 持有人、币种、余额 | 空 |
| 113 | 兑付失败退币 | 发行方、币种、持有人余额、订单 | 最终失败凭证哈希 |

开户、转账、领取的币种账户只读；其他操作币种可写。变化的余额和订单可写。账户地址绑定算法在 `programs/vm/stablecoin.go` 和 `ordexus/src/utils/stablecoinProtocol.js`；这些可公开推导的分配密钥不能授权修改既有程序状态。

## RPC

普通和公开钱包路由均提供：

- `getStablecoinCapabilities []`：版本、固定模板内容和 SHA-256、`backing=issuer_declared`、`commitment=finalized`。
- `getStablecoins [owner,cursor,limit]`：本链稳定币列表及该钱包余额。
- `getStablecoinState [mint,owner]`：发行方、供应量、声明储备、待兑付、上限、暂停、余额账户。
- `getStablecoinOrders [mint,owner,cursor,limit]`：当前发行方视图列出该币种全部订单，其他钱包视图按持有人过滤。数据本身公开，过滤不提供隐私保护。

列表按地址字典序分页，limit 为 1–100，末页 next_cursor 为空。查询只读取最终确认区块快照；快照不可用则报错，不使用尚未最终确认的 head。客户端金额不得转为浮点数。

APP 在选定 RPC 上预演、签名和广播，不自动切换网络。广播前持久化原始已签名交易；超时、重启后重播同一字节串。交易最终确认或最终确认链高超过有效期且查无交易后才允许重新发起。签名种子和明文业务编号不写入待确认记录。多个设备的操作仍需发行方以订单地址协调线下付款。

## 节点升级与验证

**此变更涉及链上执行规则，不能只更新 APP。** 必须协调验证者、公开 RPC 和钱包版本。系统程序现在禁止用状态分配密钥重建、重新分配、扩容或转走程序账户租金；运行时失败交易回滚所有前序指令，仅保留允许收取的手续费。旧版节点的上述错误行为可能产生不同状态根，因此不适合混合版本出块；现有网络须在约定边界升级，并验证历史重放/快照。当前没有自动激活高度或线上迁移流程。本次实现未部署到线上，也未广播真实资产交易。

稳定币模板 SHA-256：`4a916074a50279f88f20b2a14da91565284461e0f7524fa951fda36f4a0ad23c`。

在链项目中导出模板：`go run ./cmd/stablecoin-template`。
编辑器示例：`ordexus-studio/examples/stablecoin.ovmasm` 及同名 `.ovm.json`；使用 `cmd/ovmasm` 编译所得哈希必须与上述值一致。修改标记、manifest、syscall 或升级权限会失去稳定币模板身份。
