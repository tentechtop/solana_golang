## 当前结论

正常负载下，QUIC 与 TCP 双向中继均完成了持续通信测试；故障测试观察到连接可自动恢复。
已经修复 QUIC 端口复用、中继请求响应关联、去重缓存退化、旧连接清理及正常关闭误报等问题。
公网打洞在本次环境中尚未成功；不能把回环集成测试的直连成功等同于公网 NAT 穿透成功。

这些是短时、单公网中继测试，尚不足以证明长时间运行或任意 NAT 下的稳定性。

## 持续通信与恢复

| 持续通信 | 时间 | A→B 成功 / 失败 | B→A 成功 / 失败 | RTT 中位数 |
|---|---:|---:|---:|---:|
| QUIC 双向，1 KiB，各 1 并发，间隔 100 ms | 180 秒 | 943 / 0 | 944 / 0 | 约 85 ms |
| TCP 双向，1 KiB，各 1 并发，间隔 100 ms | 90 秒 | 487 / 0 | 486 / 0 | 约 81 ms |

QUIC 持续通信前后，A/B goroutine 均为 108；安全握手计数保持不变，说明这段测试没有重连；
结束后待处理请求为 0、队列深度为 0，也没有新增写错误或消息拒绝。
Go 堆大小有 GC 周期波动，这段观测不能证明不存在长期内存泄漏。

另外停止业务流量 70 秒（超过测试节点的 30 秒空闲阈值）后，两个节点的连接 ID 均保持不变，
说明心跳保活有效；恢复发送的 116 次请求全部成功，中位 RTT 约 84 ms。

TCP 故障注入：

- 主动关闭 A→R：连接约 104 ms 后重建，45 秒窗口 193 次成功、1 次请求超时；
  因超时请求需要等完 5 秒，首次记录到恢复成功约在注入后 5.15 秒。连接恢复与业务请求恢复分别计时。
- 重启测试中继：A/B 分别约 2.79 秒、1.09 秒重建连接；45 秒窗口 214 次成功、0 次失败，最长 RTT 约 2.74 秒。

初次 QUIC 关闭注入确实断开并恢复了连接，但控制接口收到“关闭已取消流”的错误，导致该轮脚本中止。
该问题已修复，不能把中止轮次当作完整重启测试。

修复版 QUIC 故障注入：

- 关闭 A→R：约 186 ms 重建连接、约 271 ms 恢复成功请求；45 秒窗口 233 次成功、1 次连接关闭错误。
- 重启 R：A/B 约 955 ms、859 ms 重建连接；45 秒窗口 201 次成功、1 次请求超时。
  已经在途的请求等待 5 秒超时后返回，首次记录到业务恢复约在注入后 5.34 秒。
  没有对可能已执行的业务请求自动重放，调用方仍需按业务幂等性决定是否重试。

## 打洞实现与环境边界

原实现 `quic.ListenAddr` 与 `quic.DialAddr` 分别申请 socket，监听端口与公网映射来源不一致。
修复后使用同一个 `quic.Transport`，A/B 向公网拨号的本地端口分别为 `55201`、`55202`。
三节点安全 QUIC 集成测试验证了公网协调逻辑对应的观察地址、同时拨号和实际往返。

真实公网协调曾观察到：

- 基线：A/B 均经 `183.238.213.11`，映射端口分别为 `4455`、`4456`。
- 固定监听端口后：A 经 `120.236.30.67:55201`，B 经 `120.234.26.21:55202`。
- 公网打洞调用超时，没有建立 A/B 直连；中继路径仍可使用。

最终连续 3 次公网打洞均超时；随后使用中继成功完成 106 次往返，无失败。

另行明确拨号内网地址 `192.168.1.4:55202`，QUIC 直连完成 3,080 次 64 KiB 往返、0 次失败，
有效吞吐 19.24 MiB/s，中位 RTT 3.15 ms。这个结果只代表同一机器经内网地址的直连，不能作为公网打洞成绩。

这说明两个本地进程的公网映射可能落在不同出口；仅凭一个公网观察点不能判断准确 NAT 类型。
Windows 防火墙处于启用状态，当前执行会话没有管理员权限，未修改系统防火墙。
没有完成第二个独立内网、NAT 回环能力或运营商过滤策略的实证排查。
若继续验证跨 NAT 打洞，需要将 B 放到另一台内网设备/另一网络，核对系统 UDP 放行及两端映射，
同时保留中继作为失败后的通信路径。操作命令见 [测试说明](p2p-wan-testing.md)。

## 代码改动和检查

- 新增 `Host.RequestRelay`，让真实中继请求有可靠的响应关联；安全 Host 拒绝没有来源签名的信封。
- 消费中继消息前校验内部来源、目标、协议和 ID；未验证信封不会先污染回程路由。
- 缓存过期清理由每包全表扫描改为每秒至多一次，签名校验移出缓存锁。
- QUIC 复用监听 socket；协调消息校验介绍者，拨号预算与协调时间一致，已有连接不重复启动读循环。
- 旧连接清理/关闭按连接 ID 比较，避免影响新连接。
- 取消 QUIC 流后不再重复发送 FIN，正常关闭返回正常结果。
- 直连拨号退避期间仍允许中继发送及请求；显式封禁继续拒绝。补充回退与封禁回归用例。

去重接收路径基准（无签名，10,000 个缓存条目）：约 **85,598 ns/op → 3,480 ns/op**，约 24.6 倍。
这是该本地热路径的改善，不代表公网带宽或整个 P2P 栈提升同样倍数。
